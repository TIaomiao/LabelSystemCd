# 数据集整库权限管理员操作说明

适用版本：`v2026.07.23-1` 及以后

适用角色：LabelSystem 已审核管理员

## 1. 功能用途

“数据集权限”用于把一个真实数据集的整库访问权授予已审核的普通账号。整库授权只建立访问关系，不会创建、复制、移动或重命名数据集，也不会修改已有的病例级任务分配。

入口：管理员登录后点击侧栏“数据权限”（`/admin/assignments`）；页面会自动定位到“数据集权限”区域。

本功能与“病例级任务分配”是两套独立机制：

- 整库权限：覆盖该数据集当前及以后新增的病例。
- 病例任务：只覆盖明确分配的病例；即使当前恰好覆盖全库，新增病例也不会自动加入。
- 管理员：自动继承全部数据集访问权，不需要也不能重复勾选。
- 待审核账号：不会出现在可授权列表中。

## 2. 页面状态怎么理解

| 页面状态 | 含义 | 新增病例是否自动包含 |
| --- | --- | --- |
| `系统共享` | 数据集已对所有已审核账号开放，不能重复分配 | 是 |
| `整库权限` | 账号拥有该真实数据集的整库权限 | 是 |
| `病例任务 x/y` | 账号只有 x 个当前有效病例任务 | 否 |
| `病例任务 y/y · 新增病例不自动包含` | 当前任务恰好覆盖全库，但仍不是整库权限 | 否 |
| `未授权` | 没有整库权限，也没有当前有效病例任务 | 否 |

空数据集也可以授予整库权限。一旦以后出现病例，被授权账号会自动获得访问权，因此空库授权同样需要业务审批。

## 3. 不同数据集的权限边界

页面会显示数据集的访问策略，管理员必须先核对策略再授权。

### 严格私有库

普通账号没有整库权限或精确病例任务时不能访问；管理员仍按角色自动继承。整库权限覆盖：

- 病例列表与导入；
- Study、Series 和图像；
- 轮廓、测量、报告及相关导出对象。

撤销整库权限后，账号仍可访问其保留的病例任务。要完全移除访问，还必须在“病例级任务分配”中撤销相应任务。

### 常规共享库

整库权限控制病例列表和导入，但已知 Study 的访问仍沿用系统原有的“已审核登录用户共享”规则。它不是严格隔离策略，不能把“未勾选整库权限”理解为对已知 Study 的完全拒绝。

### 系统共享库

对所有已审核账号开放，页面只展示状态，不允许重复授权或撤销。

## 4. 授予整库权限

1. 点击侧栏“数据权限”，进入页面中的“数据集权限”区域并点击“刷新权限”。
2. 在“真实数据集”下拉框中核对数据集名称和括号内的真实标识。
3. 核对目录病例数、含 DICOM 数、已导入数、数据集策略及当前整库授权人数。
4. 保存请求会携带当前修订号；如果其他管理员已经修改同一数据集，系统返回冲突提示并自动刷新，需重新核对后再保存。
5. 勾选经过业务审批的普通账号。
6. 点击“保存整库权限”，在确认框中再次核对“新增”和“移除”人数。
7. 保存成功后点击“刷新权限”，确认目标账号显示“整库权限 · 自动包含新增病例”。
8. 使用目标账号完成最小验证：能看到预期库；对于严格私有库，能访问获授权对象且不能越权访问其他私有库。
9. 展开“权限变更审计”，确认本次授予记录的管理员、账号、数据集、来源 IP 和版本号正确。

保存请求携带的是该数据集的完整整库授权名单，而不是单个增量操作。保存前必须检查是否意外取消了其他账号。

## 5. 撤销整库权限

1. 点击“刷新权限”，避免基于过期页面覆盖其他管理员刚完成的修改。
2. 选择真实数据集并取消目标账号勾选。
3. 点击“保存整库权限”，核对确认框中的移除人数。
4. 刷新页面，确认账号回到“病例任务 x/y”或“未授权”。
5. 如需完全撤权，在“病例级任务分配”中继续删除该账号的病例任务。
6. 使用目标账号验证严格私有库的列表、导入和对象访问均符合预期。
7. 在审计区域确认出现“撤销”记录。

撤销整库权限不会删除标注、测量、报告、病例、导入记录或病例任务。

## 6. 权限变更审计

每次保存只为实际发生状态变化的账号写入审计：

- 每个授予或撤销账号各一条记录；
- 同一次保存产生的记录使用同一个批次 ID；
- 保存账号和管理员的 ID、用户名快照；
- 保存真实数据集标识、显示名称快照、操作、请求来源 IP、发布版本和时间。

审计记录只追加，没有管理员更新或删除入口；SQLite 还使用触发器拒绝对审计表执行 UPDATE 或 DELETE。拥有数据库主机管理权限的人仍可移除触发器，因此数据库备份和主机权限控制仍是必要边界。普通服务日志不能替代权限审计，因为服务日志可能轮转，而且不保证完整记录业务状态变化。

页面显示审计总数和最近 100 条记录。更早记录仍保留在数据库中；如需长期导出，应走受控的数据库维护流程。来源 IP 是 Flask 收到的请求地址；在反向代理环境中可能显示代理地址，而不是最终浏览器地址。

审计从本版本上线后开始记录，不能追溯还原上线前的权限或病例任务变更。

## 7. 异常提示处理

### “已失去配置的数据集权限”

这表示数据库里存在整库授权，但对应数据集已不在当前配置中。系统不会使用这些孤立授权。不要直接修改数据库；先核对配置是否误删或改名，再通过变更流程安排清理。

### 页面加载或保存失败

- 不要连续重复点击保存。
- 记录发生时间、目标数据集、操作账号和页面错误文案，不要复制患者信息。
- 刷新页面确认实际状态；如果状态不明确，暂停同一数据集的后续授权并联系运维。

### “权限已被其他管理员修改”

这是并发保护正常生效。系统不会覆盖对方刚保存的名单；请根据自动刷新的最新状态重新勾选并保存。

### 多名管理员同时操作

本版本使用数据集修订号和服务进程内串行锁阻止旧页面静默覆盖新状态。仍建议避免多人同时维护同一数据集，并在冲突后重新核对完整名单。

## 8. 管理原则

- 只按已批准的最小权限范围授权。
- 不把“当前病例任务覆盖全库”当作整库权限。
- 不把常规共享库当作严格私有库。
- 不通过数据库脚本绕过页面和审计。
- 每次变更后同时核对有效权限与审计记录。
- 发现严格私有库越权时立即停止权限操作并按上线回滚清单处置。
