# CMR-PIPELINE-01A：验收标准

以下是计划验收项，执行前必须根据仓库真实实现补充命令和结果。

## 上传与恢复

- 小型合成 DICOM 文件夹上传成功；
- 多文件上传显示文件数和字节级进度；
- ZIP 上传能拒绝路径穿越和压缩炸弹；
- 中断后可以继续上传，已确认分片不重复传输；
- 重复分片、错误摘要和损坏归档被拒绝；
- 取消和过期任务清理暂存内容；
- 服务重启后任务不会凭空变成完成。

## DICOM Intake

- 按 SeriesInstanceUID 归组；
- 目录混排、重复 Series、缺失头和非 DICOM 文件有明确状态；
- manifest 包含版本、opaque ID、文件/instance 数量、读取状态和来源摘要；
- manifest 不包含患者标识、原始 UID、绝对服务器路径或像素内容；
- 上传成功但索引失败时不能返回 `ready_for_processing`。

## 状态与接口

- `created → preflight → uploading → verifying → indexing → ready_for_processing` 可追踪；
- 失败、取消、过期路径有稳定错误码；
- 上传状态不被算法完成状态覆盖；
- 前端刷新后仍能读取任务状态；
- 后续处理任务只能引用已验证的 manifest 版本。

## 安全与回滚

- 暂存路径不允许目录穿越；
- 文件类型、大小和数量限制在服务端执行；
- 无凭据、患者资料、DICOM、数据库或日志进入提交；
- 关闭 Intake 功能开关后既有工作流仍可运行；
- 回滚单个 commit/PR 不需要修复生产数据。

## 测试证据要求

每个用例记录 `passed / failed / not_run / blocked`、合成数据范围和实际命令。技术测试通过不升级为医生验收。

## 医生/产品检查准备

完成技术验证后准备三类检查：

1. 正常：完整小型检查，能看到上传和待处理状态；
2. 阳性：缺少某类序列但仍可用于部分功能的检查；
3. 困难：大文件、断网恢复、重复序列、残缺 Series 或非 DICOM 混入。
