## 4. SQLite 备份

生产数据库位置按以下优先级确定：`LABELSYSTEM_DATABASE_URI`、`LABELSYSTEM_DB_PATH`、默认 `backend/instance/labelsystem.db`。不要在命令输出或发布文档中暴露含凭据的数据库 URI。

以下命令只适用于 SQLite。先把变量替换为经确认的绝对路径，并把备份存入访问受控、仓库之外的目录：

```bash
export RELEASE_VERSION="v2026.07.23-1"
export DB_PATH="/absolute/production/path/labelsystem.db"
export BACKUP_DIR="/absolute/restricted/backup/path"
export BACKUP_PATH="${BACKUP_DIR}/labelsystem-${RELEASE_VERSION}-predeploy.sqlite3"

install -d -m 700 "${BACKUP_DIR}"
test -f "${DB_PATH}"
test ! -e "${BACKUP_PATH}"
sqlite3 -cmd ".timeout 30000" "${DB_PATH}" ".backup '${BACKUP_PATH}'"
sqlite3 "${BACKUP_PATH}" "PRAGMA integrity_check;"
sha256sum "${BACKUP_PATH}"
```

- [ ] `PRAGMA integrity_check` 结果为 `ok`。
- [ ] 备份文件非空、权限受限且可以由回滚负责人读取。
- [ ] 备份绝对路径、大小、SHA-256 和完成时间记录在受控发布工单。
- [ ] 没有把备份放进仓库或普通服务日志目录。
- [ ] 若现网不是 SQLite，已由数据库管理员完成对应引擎的一致性备份和恢复演练，未执行上述命令。

## 9. 回滚触发条件

出现任一情况立即停止新的整库权限操作并启动回滚评估：

- 严格私有库发生未授权访问；
- 正确授权或病例任务账号持续被错误拒绝；
- 授予/撤销状态与页面不一致；
- 实际权限变化没有对应审计，或审计记录主体错误；
- `/api/admin/dataset-access` 持续返回错误；
- 新表创建失败或数据库完整性异常；
- 新前端与后端版本不一致并造成管理错误。

## 10. 代码回滚步骤（默认）

1. 通知管理员停止权限操作，记录触发时间和症状，不复制患者内容。
2. 记录故障版本 SHA 和当前有效授权数量；不要删除审计记录。
3. 按现网进程管理方式停止 frontend Vite 和 Flask backend。
4. 前后端源码同时切回发布前已验证 SHA，并恢复原 `VERSION`/发布版本环境配置。
5. 按原生产参数先启动 Flask，再启动 frontend Vite。
6. 不重启 CVI API、Showcase 或 FRP，除非它们另有独立故障和变更批准。
7. 验证登录、病例任务、严格私有库拒绝和核心工作站流程。
8. 确认杨楠病例任务未变化，并记录回滚结果。

- [ ] 回滚后前后端版本匹配。
- [ ] 新增表默认保留，没有执行 `DROP TABLE`。
- [ ] 故障期间产生的审计记录保留用于追溯。
- [ ] 回滚原因、时间、执行人、复核人和恢复结果已写入发布工单。

旧代码不会使用新增整库授权表，因此代码回滚后，依靠新整库权限但没有病例任务的账号可能失去相应访问。这是预期的回滚效果，必须提前通知业务负责人。

## 11. 数据库恢复（仅在明确批准时）

代码回滚通常不需要恢复数据库。恢复上线前备份会覆盖上线后的所有数据库写入，包括与权限无关的正常业务数据，因此只有在以下条件全部满足时才能执行：

- 业务负责人和数据库负责人书面批准；
- 已评估并接受上线后写入丢失；
- Flask 已停止，数据库不再被写入；
- 上线前备份再次通过完整性检查；
- 当前故障数据库已另行封存，便于审计和恢复。

批准后，由数据库负责人使用受控路径执行：

```bash
export FAILED_DB_COPY="${DB_PATH}.failed-v2026.07.23-1"

test -f "${BACKUP_PATH}"
test ! -e "${FAILED_DB_COPY}"
sqlite3 "${BACKUP_PATH}" "PRAGMA integrity_check;"
cp --preserve=mode,timestamps "${DB_PATH}" "${FAILED_DB_COPY}"
sqlite3 "${BACKUP_PATH}" ".backup '${DB_PATH}'"
sqlite3 "${DB_PATH}" "PRAGMA integrity_check;"
```

- [ ] 恢复前后完整性检查均为 `ok`。
- [ ] 故障数据库副本已封存并限制访问。
- [ ] 先启动 Flask、再启动 frontend Vite，核心流程验证通过。
- [ ] 已记录因数据库恢复而丢弃的时间窗口及业务影响。

数据库恢复会同时移除备份时间点之后的权限审计，不能作为普通的“清空审计”手段。
