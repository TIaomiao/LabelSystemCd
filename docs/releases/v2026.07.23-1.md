# LabelSystem Release Note — v2026.07.23-1

发布日期：2026-07-23

发布类型：内部功能与权限安全更新

源码标识：根目录 `VERSION` + 上线记录中的 Git commit SHA

## 发布摘要

本版本新增管理员可视化的“数据集整库权限”管理。管理员可以把真实数据集授予已审核普通账号，同时保留既有病例级任务分配。整库权限自动覆盖以后新增病例，解决“当前病例任务恰好覆盖全库，但新病例不会自动加入”的问题。

本版本还新增独立、只追加的权限变更审计，记录谁在何时为哪个账号授予或撤销了哪个真实数据集，以及请求来源 IP 和发布版本。

升级本身不会自动给任何普通账号新增整库权限，也不会把现有病例任务转换成整库权限。本次生产变更已获准在上线后单独为杨楠授予 `CMR_SCS` 主库整库权限；`CMR_SCS_2`、`CMR_SCS_PAH_TEST` 和 `CMR_SCS_PAH_1` 不在授权范围。

## 新增功能

- “系统监控”页面新增“数据集权限”面板。
- 直接展示真实数据集标识、目录病例数、DICOM 数、已导入数和整库授权人数。
- 区分以下有效状态：系统共享、整库权限、当前病例任务全覆盖、部分病例任务和未授权。
- 整库权限与病例任务分离；授予或撤销整库权限均不删除病例任务。
- 管理员自动继承全部数据集；系统共享库禁止重复授权。
- 整库授权只允许分配给已审核的非管理员账号。
- 授权名单保存前显示本次新增和移除人数，减少误操作。
- 页面显示权限模块版本、审计总数和最近 100 条变更记录。

## 权限边界

- 严格私有库：整库权限覆盖病例列表、导入以及 Study、Series、图像、测量、报告和相关导出对象；没有整库权限时仍可按精确病例任务访问。
- 常规共享库：整库权限覆盖病例列表和导入；已知 Study 仍沿用已审核登录用户共享规则，并非严格隔离。
- 系统共享库：继续对所有已审核账号开放，不接受重复整库授权。
- 空数据集：允许预先授权，未来新增病例会自动纳入。

## 审计与版本

新增 `DatasetAccessAudit` 业务审计模型。实际发生变化时，每个目标账号写入一条 `grant` 或 `revoke` 记录；同一次保存用 `batch_id` 关联。记录包含：

- 数据集标识和显示名称快照；
- 目标账号 ID 和用户名快照；
- 操作管理员 ID 和用户名快照；
- 请求来源 IP、发布版本和发生时间。

应用没有更新或删除审计记录的管理入口。审计仅覆盖整库权限变更，不等同于完整的数据访问日志，也不追溯上线前历史。反向代理环境中的来源 IP 可能是代理地址。

SQLite 使用 `BEFORE UPDATE` 和 `BEFORE DELETE` 触发器拒绝篡改或删除审计行，并使用动作约束及批次目标唯一约束阻止非法或重复事件。拥有数据库主机管理权限的人员仍可移除触发器，因此该机制不能替代受控备份和主机权限管理。

版本默认读取根目录 `VERSION`。如运行环境设置了 `LABELSYSTEM_RELEASE_VERSION`，该环境变量会覆盖文件内容；上线时必须保证最终显示为 `v2026.07.23-1`。

## 数据库变更

本版本新增两张表：

- `dataset_access_grant`：保存当前整库授权状态；
- `dataset_access_audit`：保存只追加的权限变更历史。

现有 Flask 启动流程通过 `db.create_all()` 创建缺失表，不修改或删除既有表和业务数据，不需要破坏性数据迁移，也没有历史权限回填。

上线前仍必须完成 SQLite 在线备份和备份完整性检查。普通代码回滚可以保留这两张新增表；不要为了回滚代码直接执行 `DROP TABLE`。

## 部署范围

需要重启：

- LabelSystem Flask backend；
- LabelSystem frontend Vite。

本版本不需要重启：

- CVI API；
- Showcase；
- FRP。

前后端应使用同一个发布版本成对切换，避免新页面连接旧接口或旧页面误解新响应。

## 验证门禁

发布前和上线后必须按配套清单留痕，至少覆盖：

- 数据集权限后端定向测试；
- 私有数据集病例、导入和对象访问隔离测试；
- 前端 TypeScript/Vite 构建；
- 管理员与普通账号访问控制；
- 授予、撤销、病例任务保持不变和审计链路；
- 数据库新增表、版本号和备份完整性；
- 杨楠的 482 条病例任务保持不变，并按已确认变更范围新增 `CMR_SCS` 主库整库权限；补充库和两个 PAH 库保持无整库权限。

测试命令、执行人、结果和证据位置记录在[上线与回滚检查清单](v2026.07.23-1_deploy_rollback_checklist.md)中。

## 已知限制

- 权限保存采用当前数据集的完整账号名单，并使用修订号与单进程串行锁拒绝过期页面。现网应保持单 Flask 进程；如以后改为多 worker，需升级为跨进程事务锁或数据库 CAS。
- 常规共享库的已知 Study 访问仍是旧的登录用户共享策略。
- 页面只展示最近 100 条审计；完整历史需通过受控数据库维护流程查询或导出。
- 审计来源 IP 取 Flask 请求地址，未承诺穿透所有代理获得最终客户端 IP。
- 撤销整库权限不会自动撤销病例任务。

## 回滚原则

发现严格私有库越权、授权状态错误、审计缺失、持续接口错误或数据库建表失败时，应停止新的权限操作，并同步回滚 Flask backend 与 frontend Vite。

默认执行代码回滚并保留新增表。只有在业务负责人明确要求恢复到上线前数据库状态，并评估上线后其他业务写入不会丢失后，才允许恢复上线前数据库备份。完整步骤见配套检查清单。
